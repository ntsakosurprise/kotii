# GIT BRANCH NAMING GUIDLINES

## **_Guidlines_**

### Start name with category word

- This makes it clear to other people just what type of functionality this branch will have
- Category words make the intended purpose of the branch clear

**_`example`:_**

```
feat-my-awesome-new-feature
```

### Use separators

- A hyphen (-) and forward slash (/) are mostly used as separators
- A combination of the separators can be used in some cases for more clarity

**_`example`:_**

```
feat-my-awesome-new-feature
```

### Optionaly include author name

- An author's information as part of the branch-name is good for tracking
- We can quickly identify the owner of the work

**_`example`:_**

```
feat/ntsako-surprise/my-awesome-new-feature
```

### Optionaly include ticket numbers

- A ticket number is even beneficial in ticket tracking software
- Ticket numbers add more identification means on the branch

**_`example`:_**

```
feat/ntsako-surprise/123-my-awesome-new-feature
```

### Avoid long names

- Long names can create unnecessary cluter
- Long names are not to remember

**_`example`:_**

```
feat/ntsako-surprise/123-my-awesome-new-feature-thats-long-for-a-name
```

### Be descriptive

- Your branch name should clearly communicate the work to be completed
- In most cases, it should start with a verbe

**_`example`:_**

```
feat/ntsako-surprise/123-add-vivid-colors-to-home-page
```
