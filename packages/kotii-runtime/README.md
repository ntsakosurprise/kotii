`kotii-runtime` is the **production runtime layer** of the Kotii Framework.

After a Kotii application is built using `kotii-creation-time`, all heavyweight operations—such as JSX → JS, TS/TSX → JS, JSON → JS, CSV handling, bundling, minification, and code transformations—are completed during the build phase.

`kotii-runtime` then executes the **fully-optimized, pre-built output** with a minimal set of runtime utilities designed specifically for production.

---

## 📦 Installation

Usually installed automatically by Kotii build tools:

```sh
npm install kotii-runtime
```

## ⚡ What kotii-runtime Does

`kotii-runtime` loads and runs the **already-compiled and optimized** output generated by the build pipeline.  
This includes:

- Fully-transpiled JavaScript (JSX, TS, TSX, etc.)
- JSON, CSV, and other resources already converted to JS modules
- All CSS Modules resolved and tree-shaken
- TailwindCSS styles preprocessed and optimized
- Images transformed, hashed, and ready to serve
- Static assets pre-bundled and ready for production
- Zero transpilation or transformation at runtime
- Minimal plugin usage focused entirely on runtime execution

Everything heavy happens at build time.  
Everything lightweight happens at runtime.

---

## 📦 Deploy Anywhere

One of the core design goals of Kotii is portability.

After running the build pipeline via `kotii-creation-time`:

### **The output can be copied as a standalone folder and deployed on any server.**

No build tools or transpilers are required on the server—only Node.js.

This enables deployments to:

- Bare-metal servers
- Docker containers
- Serverless platforms
- Cloud VMs
- Any environment that supports Node.js ES Modules

Your build output is **self-contained**, production-ready, and requires only `@kotii/runtime` to run.

---

## 🚀 Example Usage

In production, Kotii users simply execute commands using the Kotii CLI or deployment scripts.
Under the hood, these commands dynamically load kotii-runtime

A typical usage pattern relies on **dynamic import**, ensuring the runtime is loaded only when needed:

```js
const run = (commandToRun) => {
  import("kotii-runtime").then((kotiiRuntime) => {
    const { start } = kotiiRuntime;
    start(commandToRun);
  });
};

export { run };
```

- This function is internal to Kotii and is not intended to be called directly by end users.
- Users just run Kotii commands like `kotii start` or `kotii preview`.
- The runtime ensures the correct production artifacts are executed with minimal overhead.

## What the Runtime Does Not Do

`kotii-runtime` does not perform any build-time transformations.  
It does not:

- Transpile JSX/TS/TSX
- Generate Tailwind CSS
- Process CSS Modules
- Optimize images
- Minify or bundle code

All of these are handled at build time by `kotii-creation-time`.  
Runtime only executes the already-prepared output.
